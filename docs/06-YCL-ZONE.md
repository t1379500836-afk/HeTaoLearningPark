## 需求概述

### 项目目标

为核桃编程学生提供 YCL 考级备考专区，帮助家长了解 YCL 考试价值，帮助学生进行考前练习。

### 核心价值

| 目标用户 | 核心价值 |
|---------|---------|
| **家长** | 了解 YCL 含金量、对科技特长生的帮助，提高报名意愿 |
| **学生** | 熟悉考试题型、进行模拟练习、查漏补缺 |
| **教师** | 提供备考资源、跟踪学生练习情况 |

### 设计原则

| 原则 | 说明 |
|------|------|
| **儿童友好** | 界面可爱、交互简单、不打击信心 |
| **页面精美** | 视觉吸引力强，提升学习兴趣 |
| **权威可信** | 介绍内容使用官方语言，让家长信服 |
| **循序渐进** | 练习题分难度等级，逐步提升 |

## YCL 介绍模块

### 内容要求

#### 1. 什么是 YCL

**目标**：让家长和孩子快速了解 YCL 考试

**内容要点**：
- YCL 的全称和定位
- 考试性质（全国性、标准化）
- 适用年龄/年级
- 考试形式（线上/线下）

**语言风格**：
- ✅ 官方、权威、正式
- ❌ 避免：过于口语化、夸张宣传

**示例文案**：
> 青少年人工智能编程水平测试（Youth Coding Level Test，简称 YCL）是由工业和信息化部教育与考试中心主管的全国性编程能力测评项目。该考试面向全国青少年，旨在科学、客观地评估学生的编程思维能力和代码实践能力。

#### 2. 主办方介绍

**内容要点**：
- 主管单位：工业和信息化部教育与考试中心
- 组织单位：相关权威机构
- 认可背景：国家部委背书

**示例文案**：
> YCL 考试由**工业和信息化部教育与考试中心**主管，该中心是工业和信息化部直属事业单位，负责全国信息技术领域的职业教育、技能鉴定和人才评价工作。

#### 3. 含金量说明

**内容要点**：
- 证书权威性
- 社会认可度
- 对升学的帮助
- 对个人能力的证明

**示例文案**：
> YCL 证书具有以下价值：
> - **国家认可**：由工信部教考中心颁发，电子注册，全国通用
> - **能力证明**：客观反映学生编程水平，为简历增添亮点
> - **衔接信奥**：为后续参加 CSP-J/S、NOIP 等信息学竞赛奠定基础

#### 4. 科技特长生政策

**内容要点**：
- 各地科技特长生政策概述
- 编程类证书的作用
- YCL 证书在政策中的定位
- 典型城市案例（可选）

**示例文案**：
> 近年来，全国多地在小升初、中考阶段设立"科技特长生"招生通道，编程类竞赛和考级成绩是重要的报名条件之一。YCL 作为工信部主管的权威考试，其证书在科技特长生认定中具有较高的参考价值。

#### 5. 配图要求

| 图片类型 | 用途 | 来源建议 |
|---------|------|---------|
| YCL logo | 品牌展示 | 官方网站 |
| 证书样例 | 展示含金量 | 官方或网络 |
| 考试场景 | 增加真实感 | 官方宣传素材 |
| 学生获奖/考试照片 | 激励报名 | 免费图库或授权使用 |

**图片使用规范**：
- 确保图片来源合法，避免版权问题

## 考试信息模块

### 内容要求

> **数据来源**：YCL考试信息.png（适用于四级、五级、六级）

#### 1. 题型介绍

| 题型 | 数量 | 分值 | 说明 |
|------|------|------|------|
| 单选题 | 15题 | 2分/题 | 四选一 |
| 多选题 | 5题 | 3分/题 | 多选，详见下方计分规则 |
| 编程题 | 4题 | 10+10+15+20分 | 代码编写，需老师评分 |

#### 1.1 多选题计分规则

多选题共5题，每题3分，总分15分。具体计分规则如下：

| 情况 | 得分 | 说明 |
|------|------|------|
| **全部选对** | 3分 | 选出所有正确选项，没有漏选或错选 |
| **部分选对** | 1分 | 选中了部分正确答案，但没有选错答案 |
| **选错/未答** | 0分 | 包含错误选项，或一个都没选 |

**示例**：假设某题正确答案是 **A、B、D**

| 用户选择 | 结果 | 得分 |
|---------|------|------|
| A、B、D | ✅ 全对 | 3分 |
| A、B | ⚠️ 部分正确 | 1分 |
| A、D | ⚠️ 部分正确 | 1分 |
| A、B、C | ❌ 包含错误选项C | 0分 |
| A、B、C、D | ❌ 包含错误选项C | 0分 |
| 未作答 | ❌ 未答 | 0分 |

> **重要提示**：一旦选择了错误选项，即使同时选对了部分正确答案，也 **不得分（0分）**。

#### 1.2 编程题评分说明

编程题共4题，总分55分。由于编程题需要人工审核代码逻辑，系统不自动评分：

| 题号 | 分值 | 说明 |
|------|------|------|
| 编程题1 | 10分 | 基础编程 |
| 编程题2 | 10分 | 基础编程 |
| 编程题3 | 15分 | 进阶编程 |
| 编程题4 | 20分 | 综合编程 |

**评分流程**：
1. 考生完成答题后提交试卷
2. 选择题自动评分，编程题显示"请找老师核对答案"
3. 考生需找老师核对编程题答案
4. 老师根据代码逻辑、运行结果等进行评分

#### 2. 分值分布

| 等级 | 总分 | 单选题 | 多选题 | 编程题 |
|------|------|--------|--------|--------|
| 四级 | 100分 | 30分（15题×2分） | 15分（5题×3分） | 55分（10+10+15+20） |
| 五级 | 100分 | 30分（15题×2分） | 15分（5题×3分） | 55分（10+10+15+20） |
| 六级 | 100分 | 30分（15题×2分） | 15分（5题×3分） | 55分（10+10+15+20） |

#### 3. 考试时长

| 等级 | 总时长 | 建议时间分配 |
|------|--------|-------------|
| 四级 | 90分钟 | 客观题35分钟，编程题50分钟，查漏补缺5分钟 |
| 五级 | 90分钟 | 客观题35分钟，编程题50分钟，查漏补缺5分钟 |
| 六级 | 90分钟 | 客观题35分钟，编程题50分钟，查漏补缺5分钟 |

#### 4. 考试设备要求

- **电脑（必须）**：必须使用电脑答题，需安装谷歌浏览器（Chrome），不支持手机/平板答题
- **手机（监考用）**：用于双机位监考，需下载微信，用于考试过程中的视频监考
- **网络要求**：稳定的网络连接

> **注意**：考试必须使用电脑，手机仅用于双机位监考，不能用于答题。

#### 5. 证件要求

- **身份证明证件**（任选其一）：身份证、户口本、护照
- **考试准考证**：考前打印或电子版

#### 6. 考前提醒

- 查看准考证上的考试时间
- 提前定好闹钟，避免错过考试
- 确保网络稳定
- 提前30分钟进入考试系统

## 练习题库模块

### 题库设计

#### 等级划分

| 等级 | 对应阶段 | 知识范围 |
|------|---------|---------|
| **四级** | PY1 | Python基础语法、变量、条件判断、循环 |
| **五级** | PY2 | 列表、字典、函数、字符串处理 |
| **六级** | PY3 | 算法、数据结构、综合应用 |

#### 难度分级

每个等级包含 5 套练习题：

| 难度 | 套数 | 说明 | 题目特点 |
|------|------|------|---------|
| **基础** | 3套 | 与提供的真题难度一致 | 覆盖所有必考考点，难度适中 |
| **进阶** | 1套 | 略微提升难度 | 增加综合题，考察知识迁移能力 |
| **提升** | 1套 | 较高难度 | 多知识点综合，接近考试上限 |

#### 题目生成原则

> **重要**：所有练习题必须基于用户提供的资料生成，严禁超纲！

| 原则 | 说明 |
|------|------|
| **考点覆盖** | 覆盖所有必考知识点 |
| **难度控制** | 不超出真题难度范围 |
| **题型一致** | 题型与真题保持一致 |
| **分值匹配** | 分值分布与真题一致 |
| **语言规范** | 题目表述清晰、无歧义 |

#### 复习内容（理论讲解）生成原则

> **重要**：理论讲解内容必须严格按照脚本提取的考情分析生成，严禁添加超纲内容！

| 原则 | 说明 |
|------|------|
| **内容来源** | 必须基于考情分析脚本提取的原始数据 |
| **知识范围** | 只包含该等级学生已学过的知识 |
| **方法限制** | 不添加学生未学过的函数和方法 |

**各等级知识点范围（已学内容）**：

> **重要**：以下范围以 `exam-analysis.js` 为准，当有疑问时参考该文件中的 `reviewLocation` 字段。

| 等级 | 已学内容 | 未学内容（禁止出现） |
|------|---------|---------------------|

### 权限设计

#### 路由前缀与等级对应

| 路由前缀 | 可访问等级 | 对应学生群体 |
|---------|-----------|-------------|
| `p1/` | 四级 | PY1 阶段学生 |
| `py2/` | 四级、五级 | PY2 阶段学生 |
| `python3/` | 四级、五级、六级 | PY3 阶段学生 |

#### 权限检查逻辑

```javascript
// composables/useYCLAccess.js

import { computed } from 'vue'
import { useRoute } from 'vue-router'
import { getAllowedStages } from './useRoutePrefix.js'

// YCL等级与阶段的映射
const yclLevelToStage = {
  level4: 'PY1',
  level5: 'PY2',
  level6: 'PY3'
}

// 获取当前可访问的YCL等级
export function useYCLAccess() {
  const route = useRoute()
  const prefix = getCurrentPrefix(route)
  const allowedStages = getAllowedStages(prefix)

  const accessibleLevels = computed(() => {
    const levels = ['level4'] // 四级对所有人都开放

    if (allowedStages.includes('PY2')) {
      levels.push('level5')
    }
    if (allowedStages.includes('PY3')) {
      levels.push('level6')
    }

    return levels
  })

  const canAccessLevel = (level) => {
    return accessibleLevels.value.includes(level)
  }

  return {
    accessibleLevels,
    canAccessLevel
  }
}
```

```javascript
export const levelInfo = {
  level4: {
    id: 'level4',
    name: '四级',
    fullName: 'YCL四级',
    targetStage: 'PY1',
    description: 'Python基础语法、变量、条件判断、循环',

  },
  level5: {
    id: 'level5',
    name: '五级',
    fullName: 'YCL五级',
    targetStage: 'PY2',
    description: '列表、字典、函数、字符串处理、随机数模块',
    permission: ['py2', 'python3']
  },
  level6: {
    id: 'level6',
    name: '六级',
    fullName: 'YCL六级',
    targetStage: 'PY3',
    description: '算法、数据结构、Pygame游戏开发、综合应用',
    permission: ['python3']
  }
}

// 检查是否有权限访问某等级
export function canAccessLevel(level, routePrefix) {
  const info = levelInfo[level]
  if (!info) return false
  // 无前缀时默认可访问所有等级（基础路由访问）
  if (!routePrefix) return true
  const prefix = routePrefix.toLowerCase().replace('/', '')
  return info.permission.includes(prefix)
}
```

### 踩过的坑

#### 1. Markdown `**` 加粗语法与幂运算符冲突

**问题描述**：
在理论讲解中，`**冒号**` 应该渲染为加粗的"冒号"，但之前因为要保留 Python 幂运算符 `2**3`（2的3次方），错误地移除了所有加粗处理。

**错误示例**：
```
- if 后面要有**冒号**（:）     → 渲染为：if 后面要有**冒号**（:）（未加粗）
- 2**3 = 8                      → 应保留为：2**3 = 8（幂运算）
```

**解决方案**：
使用正则表达式的负向断言，只处理 `**文字**` 模式，不处理 `数字**数字` 模式：

```javascript
// YCLPracticeView.vue - markdownToHtml 函数
// 6. 处理 ** 加粗语法（排除数字之间的幂运算符）
// 只处理 **文字** 的模式，不处理 2**3 这样的数字运算
html = html.replace(/(?<![0-9])\*\*([^*]+?)\*\*(?![0-9])/g, '<strong>$1</strong>')
```

**正则解释**：
- `(?<![0-9])` - 前面不能是数字（负向后顾断言）
- `\*\*` - 匹配两个星号
- `([^*]+?)` - 匹配中间的内容（非贪婪）
- `\*\*` - 匹配两个星号
- `(?![0-9])` - 后面不能是数字（负向前瞻断言）

**测试用例**：
| 输入 | 期望输出 |
|------|---------|
| `**冒号**` | `<strong>冒号</strong>` |
| `2**3` | `2**3`（不变） |
| `2 ** 3` | `2 ** 3`（不变） |
| `**2**3**` | `<strong>2**3</strong>` |

#### 4. 选项中的换行符显示问题

**问题描述**：
五级第一套卷子中，某道题的选项显示为 `d 1\no 2\ng 3`，其中 `\n` 没有被渲染为换行，而是显示为字面量文本。

**问题原因**：
在 `scripts/generate-sets.cjs` 脚本中使用 `JSON.stringify()` 生成数据时，换行符 `\n` 被转义为 `\\n`（字面量形式）：
```javascript
// generate-sets.cjs 第563行
export const practiceSet = ${JSON.stringify(practiceSet, null, 2)};
```

`JSON.stringify()` 会将真正的换行符 `\n`（一个字符）转换为 `\\n`（两个字符：反斜杠+n），导致前端读取数据时得到的是字面量 `\n` 而不是换行符。

**影响范围**：
- 所有级别的 `sets/*.js` 文件中的选项（options）
- `codeTemplate` 字段

**解决方案**：

1. **CSS 修复**（显示层）：
   在 `YCLExamView.vue` 中添加 CSS 属性，使换行符能正确渲染：
   ```css
   .option-text {
     flex: 1;
     white-space: pre-line;  /* 保留换行符 */
   }
   ```

2. **数据修复**（数据层）：
   创建修复脚本 `scripts/fix-escape-chars.cjs`，将 `\\n` 替换为真正的换行符 `\n`：
   ```javascript
   // 在 options 数组内，替换 \\n 为 \n
   if (inOptions && !inTestCases) {
     const newLine = line.replace(/\\\\n/g, '\n');
     if (newLine !== line) {
       modified = true;
       line = newLine;
     }
   }
   ```

3. **运行修复脚本**：
   ```bash
   node scripts/fix-escape-chars.cjs
   ```

**修复结果**：
| 文件 | 修复数量 |
|------|---------|
| level5/sets/advanced.js | 17 处 |
| level5/sets/basic-1.js | 4 处 |
| level5/sets/basic-2.js | 9 处 |
| level5/sets/basic-3.js | 8 处 |
| level5/sets/expert.js | 29 处 |
| level6/sets/basic-1.js | 16 处 |
| level6/sets/basic-2.js | 2 处 |
| level6/sets/expert.js | 1 处 |
| **总计** | **86 处** |

**注意事项**：
- `testCases` 中的 `input` 和 `expectedOutput` 字段中的 `\\n` 不需要修复，因为这些是测试用例的字面输入输出表示
- 如果重新运行 `generate-sets.cjs` 生成数据，需要再次运行 `fix-escape-chars.cjs` 进行修复

> A：使用 `\`\`\`python ... \`\`\`` 格式，注意反引号在模板字符串中需要转义为 `\`\`\``。

#### 存储工具函数

```javascript
// src/data/courses/YCL/utils/examRecord.js

const STORAGE_KEY = 'ycl_exam_records'

// 获取所有考试记录
export function getAllRecords() {
  try {
    const data = localStorage.getItem(STORAGE_KEY)
    return data ? JSON.parse(data) : {}
  } catch {
    return {}
  }
}

// 获取某等级的记录
export function getLevelRecords(level) {
  const records = getAllRecords()
  return records[level] || {}
}

// 获取某套卷的记录
export function getSetRecord(level, setId) {
  const levelRecords = getLevelRecords(level)
  return levelRecords[setId] || null
}

// 保存考试记录
export function saveRecord(level, setId, record) {
  const records = getAllRecords()
  if (!records[level]) records[level] = {}
  records[level][setId] = {
    ...record,
    submittedAt: new Date().toISOString()
  }
  localStorage.setItem(STORAGE_KEY, JSON.stringify(records))
}

// 删除某套卷记录
export function deleteRecord(level, setId) {
  const records = getAllRecords()
  if (records[level]) {
    delete records[level][setId]
    localStorage.setItem(STORAGE_KEY, JSON.stringify(records))
  }
}

// 清空所有记录
export function clearAllRecords() {
  localStorage.removeItem(STORAGE_KEY)
}
```

```javascript
// YCLExamView.vue

import { saveRecord, getSetRecord } from '@/data/courses/YCL/utils/examRecord.js'

// 状态
const reviewMode = ref(false)      // 解析模式
const reviewFromHistory = ref(false) // 是否从历史记录进入

// 提交时保存记录
function confirmSubmit() {
  showSubmitConfirm.value = false
  clearInterval(timer)
  examStarted.value = false
  examSubmitted.value = true
  calculateScore()

  // 保存到 localStorage
  saveRecord(props.level, props.setId, {
    score: calculatedScore.value,
    totalScore: practiceSet.value.meta.totalScore,
    passed: calculatedScore.value >= 60,
    answers: { ...answers.value },
    stats: {
      singleChoice: {
        correct: singleChoiceCorrect.value,
        total: singleChoiceCount.value
      },
      multipleChoice: {
        correct: multipleChoiceCorrect.value,
        total: multipleChoiceCount.value
      },
      coding: {
        score: codingScore.value,
        total: 55
      }
    }
  })
}

// 从历史记录进入解析模式
function loadHistoryAndReview() {
  const record = getSetRecord(props.level, props.setId)
  if (record) {
    answers.value = { ...record.answers }
    calculatedScore.value = record.score
    reviewMode.value = true
    reviewFromHistory.value = true
  }
}

// 判断题目是否正确
function isCorrect(q) {
  const userAnswer = answers.value[q.id]
  if (q.type === 'single-choice') {
    return userAnswer === q.answer
  } else if (q.type === 'multiple-choice') {
    return arraysEqual(userAnswer || [], q.answer)
  }
  return false
}

// 判断题目是否已答
function isAnswered(q) {
  const answer = answers.value[q.id]
  if (answer === undefined || answer === null) return false
  if (Array.isArray(answer)) return answer.length > 0
  if (typeof answer === 'string') return answer.trim().length > 0
  return true
}

// 获取导航按钮状态
function getNavStatus(index) {
  const q = questions.value[index]
  if (!isAnswered(q)) return 'unanswered'
  return isCorrect(q) ? 'correct' : 'wrong'
}
```
